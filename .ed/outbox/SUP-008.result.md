## Root cause

Code reading and mocked tests reproduce a stale session/access-check race. The password PKCE callback applies and persists member tokens, then navigates within the SPA. `SessionProvider` remains mounted across that navigation and previously checked access only on mount. Its visitor check can already have completed with `unauthorized` before the asynchronous callback exchange returns. Applying SDK tokens alone does not update React session state, so the catalog sends the newly authenticated member back to login. A subsequent attempt/page load can see the persisted member tokens, explaining the reported second-attempt behavior.

## Files changed and why

- `src/lib/authFlow.js`: after a successful password PKCE exchange has applied/persisted member tokens, await the supplied session refresh before allowing callback navigation. The Google branch is unchanged.
- `src/pages/CallbackPage.jsx`: supply the provider's stable refresh function to password completion; navigation waits for completion.
- `src/session.jsx`: expose the existing access/catalog loader as `refresh`, marking authentication not ready while it runs. The existing catalog status routing sends approved members to the catalog and franchise API 403 responses to `/pending`.
- `src/lib/authFlow.test.js`: seven mocked tests cover first-attempt success with delayed token exchange/access check, API 403 pending routing readiness, invalid-password failure, genuine email verification and owner approval states, verification-to-success without another login, and Google's existing first-attempt SDK flow. All fetches and browser globals are mocked; all fixture credentials/tokens are synthetic.
- `KANBAN.md`: updated only the existing SUP-008 card with implementation and verification status.
- `.ed/outbox/SUP-008.result.md`: this handoff.

Retained the full-page password PKCE flow rather than switching to `getMemberTokensForDirectLogin()`: Wix documents that the latter uses an iframe and can fail on mobile browsers that block third-party cookies. The defect was the missing session refresh after the exchange, not a need to repeat `login()` or bypass pending states. Reference: [Wix custom login guide](https://dev.wix.com/docs/go-headless/authentication/members/custom-login-page/build-a-custom-login-page-js-sdk).
