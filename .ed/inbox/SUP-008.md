## Bug

Samuel reports that signing in with email and password on https://supplies.daykodee.com only works on the second attempt. The first attempt with the same correct credentials fails or does not land in the catalog; the second attempt works.

Samuel also confirmed: **Google sign-in works on the first try.** Only the email+password path is broken. Do not change the Google OAuth path unless a shared helper is required for the password fix, and keep Google first-attempt sign-in working.

Do **not** reproduce against the live site and do **not** use Dwight's, Samuel's, or any other real credentials. Reproduce from code reading and from unit or integration tests that mock Wix SDK responses.

## Likely areas (email/password only)

Current password flow is `beginPasswordLogin` in `src/lib/authFlow.js` (`wix.auth.login`, then on `LoginState.SUCCESS` a custom PKCE redirect via `startPkceRedirect` and the Wix redirects API). The UI is `src/pages/LoginPage.jsx`. Tokens and `setTokens` live in `src/lib/wixClient.js`. After callback, `src/pages/CallbackPage.jsx` calls `finishOAuthCallback` and navigates to `/`; `src/session.jsx` then runs the franchise access check.

Investigate and fix:

- Wix `login()` response handling: `LoginState.SUCCESS` vs `EMAIL_VERIFICATION_REQUIRED` / `OWNER_APPROVAL_REQUIRED` (and any other non-SUCCESS state). A first response that is not yet SUCCESS, or a pending/step/redirect state, must not be treated as a hard failure if the official next step can complete the sign-in.
- Official headless email/password completion: `getMemberTokensForDirectLogin(sessionToken)` timing, and `setTokens` / `applyTokens` **before** the franchise access check or catalog redirect.
- The redirect after password login (today: PKCE + redirects-api + `/callback`). If that hop is racy or unnecessary compared with exchanging the session token for member tokens in-place, fix it so the first attempt reliably lands in the catalog (or `/pending` when the API says the member is not yet approved).
- A race between tokens being stored and the franchise access check or redirect.
- Stale state from a previous session not being cleared before a new email/password login.

Google sign-in already works on the first try (`beginGoogleSignIn` / `getAuthUrl` / `getMemberTokens`). Use that only as a contrast; do not break it.

## Fix

Make the first correct email+password attempt reliably sign the member in and land them in the catalog (or the pending-approval page when that is the correct status). Add a test that covers this first-attempt path with mocked Wix SDK responses (and mocked `fetch` / `window.location` if those are used).

Keep existing correct behavior:

- Wrong password or other real `FAILURE` still shows an error and does not enter the catalog.
- `EMAIL_VERIFICATION_REQUIRED` still asks for the email code when that is genuinely required.
- `OWNER_APPROVAL_REQUIRED` still goes to pending when that is the Wix login state.
- Google sign-in still works on the first try.
